# Plugin examples

The examples use public `mini-harness/*` imports. From the repository, run `pnpm run build` to compile all examples except the independently built Task notes package. The compiler writes JavaScript to `dist/docs/examples/`; the build copies each example's metadata and browser assets there.

Declare the **compiled directory** in a Profile's `cordis.patch.yml`. Copying a folder into a plugins directory does not activate it. The [creation walkthrough](../cookbook/creating-a-plugin.md) shows Profile initialization, absolute paths, startup and removal.

| Example                                                                                     | What it demonstrates                                                                           | Activation                                                                                                                                                           |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Greeting service](greeting-service/plugin.ts) + [Greeting route](greeting-route/plugin.ts) | A typed service, native configuration, injection and an owned HTTP route                       | Declare both compiled directories as application entries. The authenticated route is `GET /api/greeting/hello/mini-harness`.                                         |
| [Model provider](model-provider/plugin.ts)                                                  | A paired catalog and native streaming adapter with a deterministic local response              | Declare the compiled directory and select **Example echo**. See the [provider cookbook](../cookbook/adding-a-model-provider.md).                                     |
| [Process preview](process-preview/plugin.ts)                                                | Replacing the process service without changing the Shell tool                                  | Disable `core:process` and enable this entry in the same patch. Enable Shell separately. No command process is started.                                              |
| [Scoped greeting](scoped-tool/plugin.ts)                                                    | A session-scoped tool and its conversation display transform                                   | Enable Greeting service at the application level and mount this example under an existing `session:<id>` scope. It contributes to that conversation and descendants. |
| [Example panel](browser-panel/web.ts)                                                       | A page, dialog, settings category, message action and optional composer replacement            | Declare the compiled directory with `client: true`; see the [UI cookbook](../cookbook/adding-a-ui-component.md).                                                     |
| [Task notes](task-notes/README.md)                                                          | A standalone strict TypeScript plugin using sessions, runs, routes, settings, data and secrets | Build it independently, then declare its package directory with `client: true` and `live: true`.                                                                     |

For a scoped example, use the `scopes` syntax in [scoped composition](../scoped-providers.md). These examples demonstrate contracts; they do not scan or activate themselves.

## Verification

The normal build compiles the in-repository examples against the public declarations. [Composition tests](../../test/plugins/composition.test.ts) exercise the greeting and scoped examples. [Package verification](../../scripts/check-package.ts) builds Task notes and selected browser/service examples in an independent project against the installed tarball, then checks activation and removal. This does not imply that every example is exercised by every check. See [development](../development.md) for commands.
